## 一、哈希
### 1. 两数之和

这道题题干说找 `target = a + b` 的两个数 `a` 和 `b`，但如果我们换个角度，`target` 是已知的，这里就可以转换为求 `b = target - a` ，那就有意思了。

我们需要遍历数组：对每一个 `b` ，去寻找能够满足 `a = target - b` 的那一个 `a`。

但很明显：`b` 要遍历，寻找 `a` 要遍历，时间复杂度是 `O(n^2)`，如果我们将寻找的时间复杂度降到 `O(1)` 呢？

这里就可以将整个数组塞入哈希表，哈希查询的时间复杂度就是 `O(1)` 。

但要注意，题干中只让返回一个结果，我们可以不用将数组全量塞入哈希表，可以边遍历边构建哈希表，这样有两个天然的好处：
1. 如果先全量插入，当 `target - nums[i] == nums[i]` 时，可能错误地匹配到自己（除非额外处理）。而边遍历边插，保证查到的一定是**之前出现的元素**，天然排除自身。
2. 可以提前返回：一旦找到答案，就能直接提前结束遍历返回结果，性能更佳。

具体代码如下：
``` cpp
vector<int> twoSum(vector<int>& nums, int target) {
	unordered_map<int, int> map;
	for(int i = 0; i < nums.size(); i++) {      // 遍历数组，对每一个 b
		auto it = map.find(target - nums[i]);   // 寻找满足 a = target - b 的 a
		if(it != map.end()) {
			return {it->second, i};
		}
		map[nums[i]] = i;
	}
	return {};
}
```

### 49. 字母异位词分组

首先，字母异位词 = 通过重新排列不同单词或短语的字母而形成的单词或短语，并使用所有原字母一次。也就是说，能分到一起的词的字母和其数量是相同的。我们自然可以想到两种方案：
1. 对每个词进行排序，排序后相同的 `str` 就是字母异位词；
2. 统计每个词的字母及其数量，相同的就是字母异位词；

第一种方案比较简单，拉个哈希表 `unordered_map<string, vector<string>>`，以排序后的 `str` 为键，以原始字符串为值，遍历 `strs`，进行分组，最后构建结果数组输出即可：

排序法的时间复杂度是 `O(n⋅klog⁡k)` （ `k` 为单词平均长度），当单词较长时， `log⁡k` 因子不可忽视。

```cpp
vector<vector<string>> groupAnagrams(vector<string>& strs) {
	unordered_map<string, vector<string>> map;
	for(int i = 0; i < strs.size(); i++) {
		string str = strs[i];
		sort(str.begin(), str.end());
		map[str].emplace_back(strs[i]);    // emplace_back避免字符串拷贝，且`unordered_map` 的 `operator[]` 在 key 不存在时会自动对 value 进行值初始化，不用特殊处理空键
	}
	vector<vector<string>> ans;
	for(auto& m : map) {
		ans.emplace_back(m.second);
	}
	return ans;
}
```

第二种方法有点小难：对每个 `str`，构建26个字母的统计数组，`idx` 对应字母序号，`arr[idx]` 存放字母个数，然后以该数组为键，构建哈希表，后续的工作与第一种差不多，不再赘述。

这个方法的难点在需要为数组构建单独的哈希计算函数，没了解过的话很难写出来。

但这个方法理论上**时间复杂度**更优秀：
- 时间复杂度降为 `O(n⋅k)` ，省去了排序的 `log⁡k` 因子。
- 当 `k` 较大（如长文本片段）时优势明显。
```cpp
vector<vector<string>> groupAnagrams(vector<string>& strs) {
	// 哈希计算函数，简单来说就是对数组元素的每个值相加，加一次计算一次哈希，原哈希左移一位与现哈希进行异或
	auto arrayHash = [fn = hash<int>{}] (const array<int, 26>& arr) -> size_t{
		return accumulate(arr.begin(), arr.end(), 0u, [&](size_t acc, int num) {
			return (acc << 1) ^ fn(num);
		});
	};

	unordered_map<array<int, 26>, vector<string>, decltype(arrayHash)> map(0, arrayHash);
	for(string& str : strs) {
		array<int, 26> counts{};
		int length = str.length();
		for(int i = 0; i < length; i++) {
			counts[str[i] - 'a'] ++;
		}
		map[counts].emplace_back(str);
	}
	vector<vector<string>> ans;
	for(auto& m : map) {
		ans.emplace_back(m.second);
	}
	return ans;
}
```

小补充：如果使用 C++20，`std::array` 已原生支持作为 `unordered_map` 的 `key`（标准库提供了特化 `std::hash`），**完全不需要自定义哈希函数**：
```cpp
// C++20: 直接使用，零额外代码
unordered_map<array<int, 26>, vector<string>> map;
```

但主流刷题平台基本都是 C++14/17，甚至还有C++11的 （笑）

### 128. 最长连续序列

这道题要求时间复杂度为 `O(n)`，第一眼就可以直接毙掉暴力遍历，暴力起码是 `O(n^2)` 级别

既然这道题要求查找，且限制时间复杂度，那么我们一定可以想到哈希表，哈希表的查找是 `O(1)`

题干告诉我们数组中有最长连续序列，那么意味着这个最长连续序列肯定是排序后数组的一个子串，其肯定有个头，我们找到这个头即可：

设一个连续序列的头的值为 `num`，不难发现，如果要满足连续序列的要求，则在数组中肯定找不到 `num - 1`，否则 `num` 就不满足头的要求了。

既然要求连续序列，那么证明这道题肯定需要排序，由于这道题偏重查找，且不需要记录数字频次，因此我们可以使用以哈希表为底层的 `unordered_set` 记录数组内容，查找 `O(1)`，还能去重

那么整道题的思路就明了了：
- 遍历 `set` ，对每个值 `num`，查找是否存在 `num - 1`，如果不存在，说明这个 `num` 可能就是连续序列的头（包括序列长 = 1的情况）。
- 查找到后，从 `num` 开始，一直往下找 `num + 1` 、`num + 2` 、`...` 、`num + n` ，直到找不到为止，`n + 1` 就是连续序列的长度 `length`，使用 `max(ans, length)` 更新最大值，最后返回 `ans` 即可。

代码如下：

```cpp
int longestConsecutive(vector<int>& nums) {
	unordered_set<int> set(nums.begin(), nums.end());
	int ans = 0, length = 0;
	for(int num : set) {
		if(!set.count(num - 1)) {
			length = 1;
			while(set.count(++num)) length++;
			ans = max(ans, length);
		}
	}
	return ans;
}
```

## 二、双指针

### 283. 移动零

yysy，这道题很容易让人想到冒泡交换，事实上也可以这么做，代码如下：
``` cpp
void moveZeroes(vector<int>& nums) { 
	int n = nums.size(); 
	// 相邻交换
	for (int i = 0; i < n; i++) {
		for (int j = 0; j < n - 1 - i; j++) {
			if (nums[j] == 0 && nums[j+1] != 0) {
				swap(nums[j], nums[j+1]);
			}
		}
	}
}

// 搜索交换
for (int i = 0; i < n; i++) { 
	if (nums[i] == 0) { 
	for (int j = i + 1; j < n; j++) { 
		if (nums[j] != 0) { // 找到第一个非零才交换 
			swap(nums[i], nums[j]); 
			break;          // 交换后立即跳出内层 
		} 
	}
}
```

但时间复杂度为`O(n^2)`，很巧的是，这道题爆不了 TLE，但显然是不太可行的

但如果我们换个思路：题干要求我们保留非 0 数的顺序，仅将 0 移到最后，那么最后的结果是不是分为了非 0 子数组和全 0 子数组两截？

于是，我们可以使用两个指针`i`和`j`：
- 指针 `i` 是**读指针**（快指针），负责遍历数组寻找非零元素；  
- 指针 `j` 是**写指针**（慢指针），始终指向**下一个非零元素应该填入的位置**（非 0 区的右边界）。

在任意时刻，`[0, j)` 区间内全是已处理好的非零元素，且保持了原始相对顺序；`[j, i]` 区间内的元素要么是已经被前移的非零元素（原位置废弃），要么是待处理的零。

因为 `j <= i` 恒成立。写指针永远落后于或等于读指针，所以 `nums[j] = nums[i]` 这个赋值操作，要么是在原地写回（`j==i` 时，说明前面没有零，非零元素不需要移动），要么是在覆盖一个**已经被读取过或者本身就是零**的位置，绝对不会破坏尚未被 `i` 扫描到的有效数据。

算法分两步走：
- 第一步，`i` 扫描到非零值就写入 `j` 并让 `j` 后移，这相当于把所有非零元素紧凑地”挤“到数组前端；
- 第二步，当 `i` 走完整个数组后，`j` 及其之后的所有位置必然都是多余的，直接批量赋零即可。

代码如下：
``` cpp
void moveZeroes(vector<int>& nums) {
	if (nums.size() <= 1)  return;
	
	// 一次遍历，移动0
	int j = 0, n = nums.size();
	for (int i = 0; i < n; i++) {
		if (nums[i] != 0) {
			nums[j] = nums[i];
			j++;
		}
	}
	
	// 二次遍历，为 j 及 j 之后的所有元素赋 0
	for (int i = j; i < n; i++) {
		nums[i] = 0;
	}
}
```

还有一种写法，也是双指针，但是其从“遍历后赋值”，变成了“两个值交换”。这种方法同样是`O(n)`，代码更简洁，少了一次循环，但稍微多了点 `swap` 带来的写入消耗，无伤大雅：

```cpp
void moveZeroes(vector<int>& nums) {     
	int left = 0, right = 0, size = nums.size();    
	while(right < size) {         
		if (nums[right]) {             
			swap(nums[left], nums[right]);
			left++;         
		}         
		right++;     
	} 
}
```

还有一种利用标准库的邪修写法：

```cpp
void moveZeroes(vector<int>& nums) { 
	auto zero_end = remove_if(nums.begin(), nums.end(), 
		[&](int x) { return x == 0; }
	); 
	fill(zero_end, nums.end(), 0); 
} 
```

 `remove_if` 的语义是：将所有**不满足**条件（即保留）的元素按照原始顺序，紧凑地移到容器前端，返回指向新有效区间末尾的迭代器。但**被“移除”的元素仍然存在于容器中，其值处于未指定状态（valid but unspecified）**。
 
所以我们可以利用 `remove_if` 的特性，将所有 0 搬到最后。由于搬运后，原本为 0 的部分的值变成了”未指定状态“，我们必须使用 `fill` **显式赋值**这些未指定状态的元素为 0，才能保证结果正确。

### 11. 盛最多水的容器

这道题一定不能用暴力枚举，否则绝对爆 TLE

```cpp
int maxArea(vector<int>& height) {
	int n = height.size();
	int ans = 0;

	for (int i = 0; i < n; i++) {  
		for (int j = n - 1; j > i; j--) {
			int area = (j - i) * min(height[i], height[j]);
			ans = max(ans, area);
		}
	}

	return ans;
}
```

但其实这个代码就差临门一脚，该如何优化呢？

#### （1）双重循环枚举 + 剪枝：

我们可以发现，在我们遍历的时候，如果 `height[i] <= height[j]` ，也就是目前的**左柱子低于右柱子**，那么这里 `j` 就完全没有必要再向左移动遍历了：

- 面积 = `min(height[i], height[j]) * (j - i)`，宽度 `(j − i)` 是**单调递减**的，想要让面积变大，唯一的机会就是让 `min⁡(height[i],height[j])`变大。
- 而目前的矩形高度最高就是`height[i]`，所以面积只会不断减小，接下来的遍历就完全没有意义了，可以直接 `break`
- 也就是说，这里的 `break` 属于**及时止损**。

优化后的代码如下：

``` cpp
int maxArea(vector<int>& height) {
	int n = height.size();
	int ans = 0;
	for(int i = 0; i < n; i++) {
		for(int j = n - 1; j > i; j--) {
			int area = (j - i) * min(height[i], height[j]);
			ans = max(ans, area);
			// 关键：及时止损
			if(height[i] <= height[j]) {
				break;
			}
		}
	}
	return ans;
}
```

> 虽然加了 `break`，但在最坏情况下（例如数组严格递增 `[1,2,3,...,n]`），内层循环依然会跑满，时间复杂度**仍然是 `O(n^2)`** ，在 LeetCode 上依然会 TLE。

#### （2）双指针：

其实还可以使用双指针，将代码从`O(n^2)` 彻底优化为 `O(n)`：

我们知道：想要让面积变大，唯一的机会就是让 `min⁡(height[i],height[j])`变大。

单纯移动 `j`，可能会导致原本很长的柱子 `j` 被浪费掉。

假设当前 `height[i]<height[j]`，即左边是短板。

- **如果错误地移动右指针（长板）**： `j` 变成 `j−1` ，宽度减小。此时的短板依然是 `height[i]` ，所以新的 `min⁡(height[i],height[j−1])` **绝对不可能超过原来的 `height[i]`** 。所以面积**必然严格减小**，这一步是纯粹的浪费。
- **如果正确地移动左指针（短板）**： `i` 变成 `i+1` ，宽度虽然也减小了，但新的 `height[i+1]` **有可能**比原来的 `height[i]` 更高，从而突破当前的瓶颈，产生更大的面积。

也就是说，移动长板，面积上限会被当前的短板锁死，只会变小或不变；移动短板，才有可能找到更高的板子来突破上限。**我们是在“淘汰那些绝对不可能成为最优解的状态”**。

于是，我们可以进一步优化代码：

```cpp
int maxArea(vector<int>& height) {
	int n = height.size();
	int i = 0, j = n - 1;
	int ans = 0;
	while (i < j) {
		int area = (j - i) * min(height[i], height[j]);
		ans = max(ans, area);
		
		// 移动较短的柱子对应的指针
		if(height[i] <= height[j]) {
			i++;
		} else {
			j--;
		}
	}
	return ans;
}
```

### 15. 三数之和

拿到题的第一想法肯定是三重循环，但时间复杂度为 `O(n^3)` ，显然无法接受。这里有个示例：

``` cpp
vector<vector<int>> threeSum(vector<int>& nums) {
    vector<vector<int>> ans;
    sort(nums.begin(), nums.end()); // 关键：先全局排序
    int n = nums.size();
    
    for (int l = 0; l < n - 2; l++) {
        // 第一层去重：跳过重复的第一个数
        if (l > 0 && nums[l] == nums[l - 1]) continue;
        
        for (int m = l + 1; m < n - 1; m++) {
            // 第二层去重：跳过重复的第二个数
            if (m > l + 1 && nums[m] == nums[m - 1]) continue;
            
            for (int r = m + 1; r < n; r++) {
                // 第三层去重：跳过重复的第三个数
                if (r > m + 1 && nums[r] == nums[r - 1]) continue;
                
                if (nums[l] + nums[m] + nums[r] == 0) {
                    ans.push_back({nums[l], nums[m], nums[r]});
                }
            }
        }
    }
    return ans;
}
```

那么该如何修改？

三数之和为 0，本质上是在有序数组中寻找一种**平衡组合**。

而且我们可以发现，内层的两重循环本质是“在有序数组中找**两数之和**等于 target”

所以我们可以将这个问题拆分为“固定第一个数 + 两数之和“。这里推荐固定最左边的数，使用双指针 `l` 和 `r` 寻找中间和最右边的数

由于题目给的是无序数组，这里需要事先进行从小到大的排序：
- 排序后的数组，相同值挨在一起，指针移动就可以快速去重；
- 如果不事先排序，最后得到的三元组还需要进行排序去重，代价很高。

也就是说，排序后，我们可以将问题转化为：**固定最小的数，在剩余区间内用双指针寻找另外两个数使三者之和为 0**。排序不仅让双指针的单调性成立，还让相同值相邻，从而实现天然去重

这样就有了一个算法雏形：
- 对第一个数：初始化 `i = 0` ，`i` 需要遍历整个**排序好**的数组；如果 `i > 0 && nums[i] == nums[i - 1]`，则 `continue`，自然跳过重复的第一个数
- 在循环内部计算第二个数和第三个数：
	- `l = i + 1`, `r = nums.size() - 1`，`l`向右移动，`r` 向左移动，不断进行三元组计算；
	- 若三元组 `sum == 0`，则添加三元组到 `ans`，并让 `l` 和 `r` 同时前进一步；
		- 这里不用担心有问题，由于此时的三元组 `sum = 0`，如果 `r` 单独向左，仅 `r` 减小，则得到的三元组一定 `< 0`；同理，`l` 单独向右，仅 `l` 增大，得到的新三元组一定 `> 0`；
	- 然后对第二个数和第三个数进行去重，逻辑跟第一个数差不多。
	- 若`sum < 0`，则 `l++`；
	- 若`sum > 0`，则 `r--`；
	- 直到 `l >= r`，结束此次搜索，`i++`；
- 循环往复，直到 `i >= nums.size() - 2`

代码如下，补充了三个剪枝策略：
``` cpp
vector<vector<int>> threeSum(vector<int>& nums) {
	vector<vector<int>> ans;
	sort(nums.begin(), nums.end());
	int n = nums.size();
	
	for (int i = 0; i < n - 2; i++) {
		// 为第一个数去重
		if (i > 0 && nums[i] == nums[i-1]) continue;
		
		// ✅ 剪枝1：最小值已经 > 0，后面全为正数，不可能凑出和为0 
		if (nums[i] > 0) break;
		
		// ✅ 剪枝2：最小的三个数之和 > 0，后续不可能有解 
		if (nums[i] + nums[i+1] + nums[i+2] > 0) break;
		
		// ✅ 剪枝3：当前数与最大两数之和 < 0，当前数太小，跳过 
		if (nums[i] + nums[n-2] + nums[n-1] < 0) continue;
		
		int l = i + 1, r = n - 1;
		while (l < r) {
			int sum = nums[i] + nums[l] + nums[r];
			if (sum == 0) {
				ans.push_back({nums[i], nums[l], nums[r]});
				// 为第二和第三个数去重
				while (l < r && nums[l] == nums[l+1]) l++;
				while (l < r && nums[r] == nums[r-1]) r--;
				l++; r--;
			} else if (sum < 0) {
				l++;
			} else {
				r--;
			}
		}
	}
	return ans;
}
```

### 42. 接雨水

> 很经典的一道面试题，属于初见杀级别的，没相关知识储备完全不知道从何下笔。
> 
> 分三种方法：

#### （1）双指针（最优解）：

每个位置能够存储的雨水高度为 $\text{min}(\text{左侧最高柱子}, \text{右侧最高柱子}) - \text{该柱子高度}$，即：
$$water[i]=\min(leftMax,rightMax)-height[i] $$

其中：
- `leftMax`：左指针当前位置及其左侧的最大高度
- `rightMax`：右指针当前位置及其右侧的最大高度
    
双指针从数组两端向中间移动，遵循“哪边短，移动哪边”的规则：
- 若 `height[left] < height[right]`，计算左侧并移动左指针；
- 否则，计算右侧并移动右指针。

当 `height[left] < height[right]` 时，根据此前的移动过程，可以确定：
$$
leftMax \le rightMax  
$$

原因是：每一根被左指针处理过的柱子，在被越过时，右侧都存在一根比它更高的柱子。这些右侧边界都会被记录在只增不减的 `rightMax` 中。因此，所有参与更新 `leftMax` 的柱子都能被右侧边界兜住。

所以左侧当前位置的水位由 `leftMax` 决定：

```
ans += leftMax - height[left];
++left;
```

同理，当 `height[left] >= height[right]` 时，可以确定：

$$
rightMax \le leftMax  
$$

因此右侧当前位置的水位由 `rightMax` 决定：

```
ans += rightMax - height[right];
-- right;
```

完整代码如下：

``` cpp
int trap(vector<int>& height) {
    if (height.empty()) {
        return 0;
    }

    int ans = 0;
    int left = 0;
    int right = height.size() - 1;
    int leftMax = 0;
    int rightMax = 0;

    while (left < right) {
        leftMax = max(leftMax, height[left]);
        rightMax = max(rightMax, height[right]);

        if (height[left] < height[right]) {
            ans += leftMax - height[left];
            ++left;
        } else {
            ans += rightMax - height[right];
            --right;
        }
    }

    return ans;
}
```

每个位置只会被处理一次，因此：
- 时间复杂度：(O(n))
- 空间复杂度：(O(1))

> 如果不明白 `leftMax` 和 `rightMax`的更新过程，自己手推一次就比较清晰了

----

#### （2）动态规划（次优解，简单）：

动态规划的思路是：提前计算每个位置左侧和右侧的最高柱子，再套用公式。

对于位置 `i`：
$$ water[i]=\min(leftMax[i],rightMax[i])-height[i] $$
其中：
- `leftMax[i]`：位置 `i` 及其左侧柱子的最大高度
- `rightMax[i]`：位置 `i` 及其右侧柱子的最大高度

计算方式：
1. 从左向右计算 `leftMax`：
$$ leftMax[i]=\max(leftMax[i-1],height[i]) $$
2. 从右向左计算 `rightMax`：
$$rightMax[i]=\max(rightMax[i+1],height[i]) $$
3. 最后遍历每个位置，计算每个位置能够接到的雨水量，再累加得到最终结果。

代码如下：
``` cpp
int trap(vector<int>& height) {
    int n = height.size();

    if (n == 0) {
        return 0;
    }

    vector<int> leftMax(n);
    vector<int> rightMax(n);

    // 初始化
    leftMax[0] = height[0];
    rightMax[n - 1] = height[n - 1];

    // 计算每个位置左侧的最大高度
    for (int i = 1; i < n; ++i) {
        leftMax[i] = max(leftMax[i - 1], height[i]);
    }

    // 计算每个位置右侧的最大高度
    for (int i = n - 2; i >= 0; --i) {
        rightMax[i] = max(rightMax[i + 1], height[i]);
    }

    // 计算每个位置能够接到的雨水
    int ans = 0;

    for (int i = 0; i < n; ++i) {
        ans += min(leftMax[i], rightMax[i]) - height[i];
    }

    return ans;
}
```

复杂度：
- 时间复杂度：`O(n)`，需要遍历数组三次
- 空间复杂度：`O(n)`，需要两个辅助数组

> 动态规划和双指针本质上使用的是**同一个公式**。区别在于：
> 	- 动态规划提前保存所有位置的 `leftMax` 和 `rightMax`
> 	- 双指针只维护当前需要的 `leftMax` 和 `rightMax`，把空间优化到了 `O(1)`

------

#### （3）单调栈：

单调栈的思路与动态规划、双指针不同：
- 动态规划、双指针是按“竖列”计算雨水；
- 单调栈是找到左右边界后，按“横层”计算雨水。

##### 思路：

栈中存放柱子的下标，并保持对应高度从栈底到栈顶单调递减：
```
栈底 → 栈顶：高 → 低
```

当遇到一根比栈顶更高的柱子时，说明：
- 当前柱子可以作为右边界；
- 栈顶柱子是低洼处；
- 弹出栈顶后，新的栈顶可以作为左边界。

此时便形成了一个可以接水的凹槽。

##### 计算方法：

假设有：
```
left      bottom          right
左边界     凹槽底部         右边界
```

凹槽宽度为：
$$width=right-left-1$$
这一层雨水的高度为：
$$ waterHeight=\min(height[left],height[right])-height[bottom] $$
因此，本次增加的雨水量为：
$$ water=width\times waterHeight $$

##### 代码如下：
``` cpp
int trap(vector<int>& height) {
	if (height.empty()) {
        return 0;
    }
    
    int n = height.size();
    int ans = 0;
    stack<int> st;

    for (int right = 0; right < n; ++right) {
        // 当前柱子比栈顶柱子高，说明可能形成凹槽
        while (!st.empty() && height[right] > height[st.top()]) {
            // 凹槽底部
            int bottom = st.top();
            st.pop();

            // 没有左边界，无法接水
            if (st.empty()) {
                break;
            }

            // 弹出 bottom 后，新的栈顶是左边界
            int left = st.top();

            int width = right - left - 1;
            int waterHeight =
                min(height[left], height[right]) - height[bottom];

            ans += width * waterHeight;
        }

        st.push(right);
    }

    return ans;
}
```

##### 为什么需要循环弹栈？

```
while (!st.empty() && height[right] > height[st.top()])
```

- 一根较高的右边界可能一次填平多个低洼层。
- 每弹出一个栈顶，就结算一层雨水，然后继续检查当前柱子是否还能填平更高的一层。

##### 总结：

单调栈维护的是一个高度单调递减的柱子序列：
1. 当前柱子不高于栈顶：直接入栈，等待右边界；
2. 当前柱子高于栈顶：弹出栈顶，将其作为凹槽底部；
3. 新的栈顶作为左边界，当前柱子作为右边界；
4. 按“宽度 × 高度”计算一层雨水。

复杂度：
- 时间复杂度：`O(n)`，每个下标最多入栈、出栈一次；
- 空间复杂度：`O(n)`，最坏情况下所有下标都进入栈。

## 三、滑动窗口

> **有双指针 ≠ 滑动窗口。** 只有当左指针具有**单调性**（只增不减）、状态可以**增量复用**时，才叫滑动窗口；否则只是用双指针包装的暴力枚举。

### 3. 无重复字符的最长子串

这道题如果用暴力，复杂度在 `O(n^3)`（最朴素三重循环） 或 `O(n^2)`（下面的写法），会爆 TLE

下面这种写法虽然能够说是双指针，但本质上还是双层循环
``` cpp
int lengthOfLongestSubstring(string s) {
	int ans = 0, n = s.length();
	for(int l = 0; l < n; l++) {
		unordered_map<char, int> map;
		int len = 0;
		for(int r = l; r < n; r++) {
			if(map.count(s[r])) {
				break;
			}
			len++;
			map[s[r]] ++;
		}
		ans = max(len, ans);
	}
	return ans;
}
```

仔细读题，我们可以发现，假如右指针碰到了一个已有的字符，我们要想将已有的子串重新化为不重复的子串，只需要**将已有字符及其之前的所有字符全部删除**即可，即将左指针移动到**已有字符的后一个位置**。
- 比如`abcdefc`，如果右指针指向第二个 `c`，则左指针需要移动到 `d`，才能让现有子串变为无重复子串。

那么上面的代码就可以优化成这样：
```cpp
int lengthOfLongestSubstring(string s) { 
	unordered_map<char, int> map; 
	int ans = 0, l = 0; 
	for (int r = 0; r < s.size(); ++r) { 
		// 发现重复 → 收缩左边界（而不是重置！） 
		while (map.count(s[r])) { 
			map.erase(s[l]); ++l; 
		} 
		map[s[r]]++; 
		ans = max(ans, r - l + 1); 
	} 
	return ans;
}
```

由于是不重复子串，不用统计频次，我们也可以用 `unordered_set`，更方便：
```cpp
int lengthOfLongestSubstring(string s) {
	unordered_set<char> set;
	int n = s.size();
	int l = 0, ans = 0;
	for(int r = 0; r < n; r++) {
		while(set.find(s[r]) != set.end()) {
			set.erase(s[l]);
			l++;
		}
		ans = max(ans, r - l + 1);
		set.insert(s[r]);
	}
	return ans;
}
```

还有一种极端优化：由于题目说 `s` 由英文字母、数字、符号和空格组成，标准 ASCII 含 128 个字符，可打印字符共有 95 个。所以可以开个静态数组 `arr[128]` 记录每个字符在字符串中最后出现的位置，令左指针收缩时可以查表实现一步跳转。

```cpp
int lengthOfLongestSubstring(string s) {
	int ans = 0;
	array<int, 128> arr{};
	int l = 0;
	for (int r = 0; r < s.size(); r++) {
		l = max(l, arr[s[r]]);
		arr[s[r]] = r + 1;
		ans = max(ans, r - l + 1);
	}
	return ans;
}
```

### 438. 找到字符串中所有字母异位词

这道题不像上道题，上道题是变长窗口，需要进行多次滑动；这道题是定长窗口，有固定的窗口大小 `p.size()`，且一次只滑 1 位。

字母异位词（Anagram）要求的是**字符种类和数量都完全相同**，而 `set` 只记录字符“有没有”，所以这道题必须退回到**频次数组**，不能使用 `set` 。

由于只有小写字母，我们可以使用**定长数组**作为频次数组。

代码如下：

```cpp
vector<int> findAnagrams(string s, string p) {
	int sLen = s.size(), pLen = p.size();
	if (sLen < pLen) return {};

	vector<int> ans;
	array<int, 26> window{}, p_arr{};

	// 初始化p的频次数组和第一个窗口
	for (int i = 0; i < pLen; ++i) {
		++p_arr[p[i] - 'a'];
		++window[s[i] - 'a'];
	}

	// 比较第一个窗口和p的频次数组
	if (window == p_arr)
		ans.push_back(0);

	// 窗口滑动
	for (int r = pLen; r < sLen; r++) {
		window[s[r] - 'a']++;          
		window[s[r - pLen] - 'a']--;

		// 比较当前窗口和p的频次数组
		if (window == p_arr)
			ans.push_back(r - pLen + 1);
	}

	return ans;
}
```

还有个进阶优化：

对整个数组进行比较，每次都要比较 26 个整数，虽然常数小，但时间复杂度仍有 `O(26)` 。

可以用一个变量 `diff` 实时维护窗口与目标的差异数，将比较降为 `O(1)` 

这里使用了平衡数组的思想：`cnt[c] = 窗口中idx=c字母的个数 − p中idx=c字母的个数`
- `cnt[c] == 0` → 窗口中 `c` 的数量**恰好等于** `p` 中 `c` 的数量 ✅
- `cnt[c] > 0` → 窗口中 `c` **多了** ❌
- `cnt[c] < 0` → 窗口中 `c` **少了** ❌

而 `diff` 记录 `cnt` 数组中**非零元素的个数**。
- `cnt[c] == 0` → 该字符平衡 ✅
- `cnt[c] ≠ 0`（无论正负）→ 该字符不平衡 ❌

所以，`diff == 0` ⟺ 所有26个字符的 `cnt` 都为0 ⟺ 所有字符都平衡 ⟺ 窗口与 `p` 是字母异位词

滑动时，每次进出只影响一个字符的 `cnt` 值。只需检查该字符在操作前后是否**跨越了零点**，即可 `O(1)` 更新 `diff`，无需遍历整个数组。

> **关键细节：`diff` 的更新必须与 `cnt` 的修改严格交错，不可合并。**

因为 `diff` 的变化取决于 `cnt[x]` **是否跨越零点**，这要求我们同时知道“修改前”和“修改后”两个状态。若先改 `cnt` 再算 `diff`，旧状态即丢失，无法判断是“从 0 变非 0 ”还是“从非 0 变 0 ”。

**正确时序：**
1. 检查旧值：若 `cnt[x] == 0`，则 `diff++`（即将打破平衡）；
2. 执行修改：`cnt[x]++` 或 `cnt[x]--`；
3. 检查新值：若 `cnt[x] == 0`，则 `diff--`（重新恢复平衡）。

只有遵循此顺序，才能确保每次滑动窗口时 `diff` 的 `O(1)` 更新准确无误。

```cpp
vector<int> findAnagrams(string s, string p) {
    int sLen = s.size(), pLen = p.size();
    if (sLen < pLen) return {};

    vector<int> ans;
    int cnt[26] = {};
    int diff = 0;  // cnt[i] != 0 的种类数

    // 初始化：cnt = win - pat
    for (int i = 0; i < pLen; ++i) {
        ++cnt[s[i] - 'a'];
        --cnt[p[i] - 'a'];
    }
    // 同时统计 diff
    for (int i = 0; i < 26; ++i)
        if (cnt[i] != 0) ++diff;
	
	// 如果 diff == 0，则代表两窗口是字母异位词，添加 0 索引
    if (diff == 0) ans.push_back(0);

    for (int r = pLen; r < sLen; ++r) {
        // 右端字符进入
        int in = s[r] - 'a';
        if (cnt[in] == 0) diff++;      // 从平衡变为不平衡
        cnt[in]++;
        if (cnt[in] == 0) diff--;      // 从不平衡恢复平衡

        // 左端字符离开
        int out = s[r - pLen] - 'a';
        if (cnt[out] == 0) diff++;
        cnt[out]--;
        if (cnt[out] == 0) diff--;

        if (diff == 0) ans.push_back(r - pLen + 1);
    }
    return ans;
}
```

## 四、子串

### 560. 和为 K 的子数组

#### 1. 暴力枚举

这道题能暴力枚举，时间复杂度为 `O(n^2)`

```cpp
int subarraySum(vector<int>& nums, int k) {
	int n = nums.size(), ans = 0;
	for(int i = 0; i < n; i++) {
		int sum = 0;
		for(int j = i; j < n; j++) {
			sum += nums[j];
			if(sum == k) {
				ans += 1;
			}
		}
	}
	return ans;
}
```


但暴力枚举显然不合适。

#### 2. 前缀和 + 哈希表：

##### 分析：

> 这道题的核心难点在于：**子数组是连续的**，且数组中**包含负数**，当窗口和超过 `k` 时，收缩左边界不一定能让和减小（可能下一个元素是负数），所以无法保证单调性，因此不能使用滑动窗口。
> **前缀和 + 哈希表**是解决此问题的最优解法。

##### 1. 数学转化：从"子数组和"到"两数之差"

定义前缀和 `prefix[i]` = `nums[0] + nums[1] + ... + nums[i-1]`（即前 i 个元素的和）。

那么任意一个连续子数组 `[j, i]` 的和可以表示为： $$sum(j, i) = prefix[i+1] - prefix[j]$$
题目要求 `sum(j, i) == k`，其等价于： $$\begin{align} prefix[i+1] - prefix[j] = k \\ \Rightarrow prefix[j] = prefix[i+1] - k \end{align}$$

> **💡 关键洞察**：当我们遍历到位置 `i` 时，`prefix[i+1]` 是已知的当前前缀和。我们只需要知道：**在之前的所有前缀和中，有多少个等于 `prefix[i+1] - k`**。每一个这样的前缀和都对应一个合法的子数组。

##### 2. 为什么用哈希表？

暴力做法是对每个 `i`，遍历所有 `j < i` 检查条件，时间复杂度 $O(n^2)$。

但我们的查询本质是：**"某个值在之前出现过几次"**——这正是哈希表的强项：

|操作|含义|复杂度|
|:--|:--|:--|
|`map[prefix - k]`|查询目标值出现次数|$O(1)$|
|`map[prefix]++`|记录当前前缀和|$O(1)$|

于是，哈希表便可以将 $O(n)$ 的内层查找降为 $O(1)$，总体 $O(n)$。

##### 3. 为什么需要 `map[0] = 1`？

这是最容易遗漏的细节。考虑以下场景：

```
nums = [3], k = 3
```

- 遍历到 `num=3` 时，`prefix = 3`
- 需要查找 `prefix - k = 3 - 3 = 0`
- 这个 `0` 代表的是 **"空前缀"**（即子数组从索引 0 开始的情况）

如果不预设 `map[0]=1`，就会漏掉所有**从数组开头开始的合法子数组**。

> `map[0] = 1` 的语义：前缀和为 0 的状态在数组开始前就已经存在了 1 次。

##### 4. 总结模板

```
prefix = 0, map = {0: 1}, result = 0
for num in nums:
    prefix += num
    result += map[prefix - k]   // 查：之前有几个前缀和能与当前配对
    map[prefix]++               // 存：把当前前缀和加入历史记录
```

这个模式适用于所有 **"连续子数组 + 和/异或/模运算 + 计数"** 类问题，是必须掌握的基础范式。

这道题的具体代码如下：

``` cpp
int subarraySum(vector<int>& nums, int k){
	int result = 0;
	vector<int> prefix(nums.size() + 1){};
	unordered_map<int, int> prefix_map;
	prefix_map[0] = 1;

	for(int i = 0; i < nums.size(); i++){
		prefix[i+1] = prefix[i] + nums[i];
	}
	
	for(int i = 0;i < nums.size(); i++){
		result += prefix_map.count(prefix[i+1]-k) ? prefix_map[prefix[i+1]-k] : 0;
		prefix_map[prefix[i+1]] ++;
	}
	return result;
}
```

还可以将 prefix 数组优化为一个单独的滚动前缀和变量，可以省掉一个数组的 `O(n)` 额外空间：

```cpp
int subarraySum(vector<int>& nums, int k) {
	int result = 0;
	int prefix = 0;                          // 滚动前缀和，替代 prefix 数组
	unordered_map<int, int> prefix_map;
	prefix_map[0] = 1;                       // 空前缀和为0，出现1次

	for (int num : nums) {
		prefix += num;
		result += prefix_map[prefix - k];     // 单次查找，key不存在自动返回0
		prefix_map[prefix]++;                 // 添加前缀和到记录表
	}
	return result;
}
```

### 239. 滑动窗口最大值

#### 分析：

暴力枚举死定了 : )

``` cpp
vector<int> maxSlidingWindow(vector<int>& nums, int k) {
	vector<int> ans{};
	int n = nums.size();
	int r = k - 1;
	for(int l = 0; l <= n - k; l++) {
		int maxNum = INT_MIN;
		for(int i = l; i <= r; i++) {
			maxNum = max(maxNum, nums[i]);
		}
		ans.emplace_back(maxNum);
		r++;
	}
	return ans;
}
```

对于每个窗口，都要遍历 `k` 个元素找最大值，时间复杂度是 `O(n × k)` 。  

其核心浪费在于：**相邻两个窗口有 `k−1` 个元素是重叠的**。你明明已经在上一个窗口里比较过它们了，下一个窗口又重新比较了一遍。

#### **优化思路**：

> **能不能维护一个数据结构，在窗口滑动时，只花 `O(1)` 的时间就能知道当前窗口的最大值？**

让我们来想个问题：

> 假设当前窗口里有三个数：`[..., 5, 3, ...]`，且 `3` 在 `5` 的右边。  
> 请问：`3` 还有可能成为未来某个窗口的最大值吗？  

答：**绝对不可能**。 因为只要 `3` 还在窗口里，`5` 就一定也在窗口里（`5` 比 `3` 晚出窗口）。而 `5 > 3`，所以最大值永远是 `5`，轮不到 `3`。

**结论**：如果一个新进来的元素比前面的元素大，那么前面那些比它小的元素就可以**永久删除**了。它们既不是当前窗口的最大值，也不可能是未来窗口的最大值。

那如何快速删除那些比该元素小的元素呢？无序肯定不好删，所以必须排序，我们不需要数组的随机访问能力，所以可以选择队列，但我们需要在同一边弹出元素和插入元素，所以只能选择**双端队列 `deque`**

#### 单调队列：

基于上面的洞察，我们维护一个**双端队列（deque）**，保证队列里的元素**从队头到队尾单调递减（非严格）**。

队列里存的不是值，而是值对应的**数组下标**（因为你需要判断元素是否滑出窗口）。

这个队列的含义是：**“当前及未来可能成为最大值的候选人列表”**。

- **队头**：当前窗口的最大值。
- **队尾**：最新加入的、目前最小的候选人。

#### 算法：
| 操作   | 做什么                          | 为什么                |
| :--- | :--------------------------- | :----------------- |
| 入队   | 新元素进来前，把队尾所有比它小的元素弹出，然后自己入队尾 | 维持“递减”性质，淘汰不可能的候选人 |
| 出队   | 检查队头下标是否已滑出窗口左边界，若是则弹出       | 过期的最大值不能再用了        |
| 取最大值 | 直接读队头元素                      | 递减队列的队头就是当前最大值     |

#### 代码：
```cpp
vector<int> maxSlidingWindow(vector<int>& nums, int k) {
    deque<int> dq; // 存下标，保证对应值从队头到队尾递减（降序排列，在队尾增删）
    vector<int> ans;
    
    for (int i = 0; i < nums.size(); i++) {
        // 【出队】队头过期了就扔掉
        // 由于下标是按顺序入队的，若队头未过期，则队内所有元素都未过期。因此只需检查队头。
        // 窗口左边界是 i-k+1，队头下标 < 左边界说明已滑出
        while (!dq.empty() && dq.front() < i - k + 1) {
            dq.pop_front();
        }
        
        // 【入队】维护递减性：新元素比队尾大，队尾就没资格当候选人了
        // 为什么用 >= : 相等时弹出旧的、保留新的，因为新下标更晚过期，能当更久的候选人。
        while (!dq.empty() && nums[i] >= nums[dq.back()]) {
            dq.pop_back();
        }
        dq.push_back(i);
        
        // 【取答案】等待第一个窗口形成。当第一个窗口形成后（i >= k-1），队头就是最大值，后续每循环一次，窗口前进一格，返回一次最大值
        if (i >= k - 1) {
            ans.push_back(nums[dq.front()]);
        }
    }
    return ans;
}
```

**单调队列的时间复杂度：O(n) 
- 每个下标最多入队一次、出队一次（无论是队头过期弹出还是队尾淘汰弹出），总操作次数为 `2n` ，每元素均摊 `O(1)`

### 76. 最小覆盖子串

这道题暴力是解不出来滴~ 用 jio 想都能想明白，遍历字符串的双重循环 + 比对字符串 `t` 的一层循环，复杂度能到 `O(n^3)`，在力扣上直接能判死刑。

这道题仍然采用滑动窗口，没归到“滑动窗口”章节是因为这道题主要在子串上下文章，滑动窗口只是工具。

但这道题难点在于：什么时候该收缩窗口？

滑动窗口框架只有两步：右边界扩张、左边界收缩。

- **扩张**是无脑的：为了找齐所有字符，`right` 必须一直向右走。
- **收缩是有条件的**：只有在当前窗口**已经完全覆盖**了 `t` 的所有字符时，我们才有资格尝试缩小窗口（否则越缩越缺）。

所以，整个算法的灵魂就在于：**如何高效判断“当前窗口是否已覆盖 `t`”？**

正常的思路是在每次移动指针后都遍历哈希表，对比计数数组 `window` 和 `need` 的每个字符计数，这里的开销为 `O(|Σ|)` ，放循环里只会超时。

所以，我们可以使用一个整数变量 `formed/valid` 来**增量维护**当前的覆盖状态： 
- 当某个字符在窗口中的数量**刚好达到** `t` 中要求的数量时，`formed++`。
- 当某个字符在窗口中的数量**跌破**要求时，`formed--`。
- 当 `formed == need.size()` 时，窗口合法！

这样，判断覆盖子串的时间复杂度就从 `O(|Σ|)` 降到了  `O(1)` 。

> 跟 `438. 找到字符串中所有字母异位词` 的 `diff` 意思差不多，那边是差异计数，要求`diff == 0`，这边是状态匹配， 要求 `formed == need.size()`

| 维度   | 438.字母异位词    | 76.最小覆盖子串               |
| :--- | :----------- | :---------------------- |
| 状态变量 | `diff`（差异计数） | `formed`（已匹配种类数）        |
| 合法条件 | `diff == 0`  | `formed == need.size()` |
| 窗口大小 | 固定 `len(t)`  | 动态变化                    |
| 更新时机 | 入窗/出窗时增减     | 入窗/出窗时按需增减              |

代码：
```cpp
string minWindow(string s, string t) {
    unordered_map<char, int> need, window;
    for (char c : t) need[c]++;
    
    int left = 0, formed = 0;
    int minLen = INT_MAX, start = 0; // 记录最优窗口的起始位置和长度
    
    for (int right = 0; right < s.size(); right++) {
        // 【扩张】新字符入窗
        char c = s[right];
        // 统计字符
        if (need.count(c)) {
            window[c]++;
            // 刚好达标，formed++（注意是 == 不是 >=，避免重复计数）
            if (window[c] == need[c]) {
                formed++;
            }
        }
        
        // 【收缩】窗口合法时，尝试缩小
        // 注：need.size() 等价于 t 中不同字符的种类数，而不是 t 的长度
        while (formed == need.size()) {
            // 当目前解 < 历史最优解时，更新历史最优解
            if (right - left + 1 < minLen) {
                minLen = right - left + 1;
                start = left;
            }
            
            // 左边界字符出窗
            char d = s[left];
            if (need.count(d)) {
                // 出窗前刚好达标，出窗后就要跌破了，所以 formed--
                if (window[d] == need[d]) {
                    formed--;
                }
                window[d]--;
            }
            left++;
        }
    }
    
    return minLen == INT_MAX ? "" : s.substr(start, minLen);
}
```


**时间复杂度：O(n)** 
- `left` 和 `right` 指针各自最多遍历 `s` 一次，不会回退；哈希表操作均摊 `O(1)` 。总时间复杂度为 `O(n+m)` ，其中 `n = |s|`, `m = |t|`。

### 53. 最大子数组和

很不出意外的是，暴力过不了 : )
- PS：就没见过力扣暴力能过几道题

```cpp
int maxSubArray(vector<int>& nums) {
	int n = nums.size(), ans = INT_MIN;
	for(int l = 0; l < n; l++) {
		int sum = INT_MIN;
		for(int r = l; r < n; r++) {
			if(sum == INT_MIN)  sum = nums[r];
			else                sum += nums[r];
			ans = max(ans, sum);
		}
	}
	return ans;
}
```

#### 1. 动态规划

由于“连续子数组”天然具有**向后延伸**的性质。如果我们知道以 `i-1` 结尾的最优解，就能在 `O(1)` 内推导出以 `i` 结尾的最优解。

此时，站在位置 `i`，你只有两个选择：

| 选择         | 含义                         | 对应表达式               |
| ---------- | -------------------------- | ------------------- |
| **接上前面的**  | 前面的累积和对当前有正贡献，拼起来更大        | `dp[i-1] + nums[i]` |
| **自己另起炉灶** | 前面累积和是负的，拖后腿了，不如从 `i` 重新开始 | `nums[i]`           |

取两者较大值，就是“以 `i` 结尾”的最优解。即：$\text{dp}[i] = \max((\text{dp}[i - 1] + \text{nums}[i]),\space \text{nums}[i]);$

这一步本质上是在决定：**要不要丢弃前面的历史包袱。**

代码如下：
```cpp
int maxSubArray(vector<int>& nums) {
	int n = nums.size();
	vector<int> dp(n);
	dp[0] = nums[0];
	int ans = dp[0];
	for(int i = 1; i < n; i++) {
		dp[i] = max(dp[i - 1] + nums[i], nums[i]);
		ans = max(ans, dp[i]);    // 注意：记得更新全局最优解，dp[i] 仅保证“以 i 结尾”是最优，也就是说，全局最优解可能在整个dp数组中，而不是 dp.back()
	}
	return ans;
}
```

由于这道题更新 `dp` 时，后面的 `dp[i]` 只依赖 `dp[i - 1]`，所以此处可以直接省略掉 `dp` 数组，改用单变量作为 `dp` 记录：

```cpp
int maxSubArray(vector<int>& nums) {
	int dp = 0, ans = nums[0];
	for(const auto& x : nums) {
		dp = max(dp + x, x);
		ans = max(ans, dp);
	}
	return ans;
}
```

动态规划的时间复杂度为 `O(n)`，仅需一次遍历；空间复杂度根据使用 `dp` 数组还是 `dp` 变量，分别为 `O(n)` 和 `O(1)`

#### 2. 分治

对于区间 $[l,r]$，设中点为 $m$。最大子数组只有三种可能：
1. 完全位于左半区间 $[l,m]$
2. 完全位于右半区间 $[m+1,r]$
3. 横跨中点

前两种可以递归求解，关键是如何高效计算第三种。

一种直接做法是：
- 从 `m` 向左扫描，求最大==后缀==和；
- 从 `m + 1` 向右扫描，求最大==前缀==和；
- 两者相加就是横跨中点的最大子数组和。

代码如下：
```cpp
class Solution {
public:
    int divide(const vector<int>& nums, int left, int right) {
	    // l = r，递归结束，返回上一层
        if (left == right) {
            return nums[left];
        }
		
        int mid = left + (right - left) / 2;
		
		// 递归分治，求解完全位于左/右半区间的最大子数组和
        int leftMax = divide(nums, left, mid);
        int rightMax = divide(nums, mid + 1, right);
		
		// 计算中点左半截的后缀和
        int leftSuffix = INT_MIN;
        int sum = 0;
        for (int i = mid; i >= left; --i) {
            sum += nums[i];
            leftSuffix = max(leftSuffix, sum);
        }
		
		// 计算中点右半截的前缀和
        int rightPrefix = INT_MIN;
        sum = 0;
        for (int i = mid + 1; i <= right; ++i) {
            sum += nums[i];
            rightPrefix = max(rightPrefix, sum);
        }
		
		// 这俩加起来就是跨中点的最大子数组和
        int crossMax = leftSuffix + rightPrefix;
		
		// 返回这三个中最大的一个
        return max({leftMax, rightMax, crossMax});
    }

    int maxSubArray(vector<int>& nums) {
	    // 分治
        return divide(nums, 0, nums.size() - 1);
    }
};
```

时间复杂度是：`O(n log n)`
空间复杂度为递归栈的：`O(log n)`

**但还有个更漂亮的分治写法：用四个区间信息进行分治。**

对于每个区间，我们维护四个量：

|名称|含义|合并时的直觉理解|
|:--|:--|:--|
|`sum`|整个区间的元素和|左右直接相加|
|`lmax`|必须从左端点开始的最大和|要么只用左半边的 lmax，要么吃掉整个左半边再拼右半边的 lmax|
|`rmax`|必须在右端点结束的最大和|要么只用右半边的 rmax，要么吃掉整个右半边再拼左半边的 rmax|
|`mmax`|区间内任意位置的最大和|左边内部最优 / 右边内部最优 / 跨越中线（左rmax+右lmax） 三选一|

例如区间：
```
[-2, 3, -1]
```

对应信息为：
- `sum = 0`
- `lmax = 0`，即整个 `[-2, 3, -1]`
- `rmax = 2`，即 `[3, -1]`
- `mmax = 3`，即 `[3]`

假设区间被分成左右两部分：

```
[ 左区间 ][ 右区间 ]
```

左右区间的信息分别为 `left` 和 `right`。

则区间总和 $sum = left.sum + right.sum$

最大前缀有两种选择：
1. 只使用左区间的最大前缀；
2. 使用整个左区间，再接上右区间的最大前缀。

即：最大前缀和 $lmax=\max(left.lmax,\ left.sum+right.lmax)$

同理：最大后缀和 $rmax=\max(right.rmax,\ right.sum+left.rmax)$

此时最大子数组有三种可能：
1. 完全位于左区间；
2. 完全位于右区间；
3. 横跨两个区间。

横跨时，必须是：`左区间最大后缀 + 右区间最大前缀`

因此：$mmax=\max(left.mmax,\ right.mmax,\ left.rmax+right.lmax)$

整理为代码如下：
```cpp
class Solution {
    struct Status {
        int sum;    // 区间总和
        int lmax;   // 最大前缀和
        int rmax;   // 最大后缀和
        int mmax;   // 最大子数组和
    };

    Status merge(const Status& left, const Status& right) {
        Status result;

        result.sum = left.sum + right.sum;

        result.lmax = max(left.lmax, left.sum + right.lmax);

        result.rmax = max(right.rmax, right.sum + left.rmax);
		
        result.mmax = max({left.mmax, right.mmax, left.rmax + right.lmax});

        return result;
    }

    Status divide(const vector<int>& nums, int left, int right) {
	    // 递归结束，退回上一层
        if (left == right) {
            int value = nums[left];
            return {value, value, value, value};
        }
		
        int mid = left + (right - left) / 2;

        Status leftStatus = divide(nums, left, mid);
        Status rightStatus = divide(nums, mid + 1, right);
		
        return merge(leftStatus, rightStatus);
    }

public:
    int maxSubArray(vector<int>& nums) {
        return divide(nums, 0, nums.size() - 1).mmax;
    }
};
```

- 时间复杂度：`O(n)`
- 递归栈空间复杂度：`O(log n)`

#### 总结：

这类方法的关键并不是“把数组二分”，而是设计一种可以合并的区间状态：
```
左区间状态 + 右区间状态 → 整个区间状态
```

只保存 `mmax` 是不够的，因为父区间的最大子数组可能横跨中点。为了计算横跨中点的情况，还需要：
```
左区间的最大后缀和 + 右区间的最大前缀和
```

为了继续计算父区间的最大前缀和与最大后缀和，又必须保存 `sum`。因此最终得到四个量：
```
sum、lmax、rmax、mmax
```

分治算法是“临时递归计算这些信息”；线段树则是“将所有区间信息保存起来，以支持查询和修改”。

### 56. 合并区间

> 这道题推荐使用 **排序 + 贪心/双指针** 的思路进行解决。

#### 1. 为什么要排序？

想象你桌面上有一堆乱七八糟的纸条，每张纸条上写着一个时间段（比如 `[3,6]`, `[1,4]`, `[8,10]`）。  
如果它们乱序摆放，你每拿一张新纸条，都要和桌上**所有**已有的纸条比对是否重叠，复杂度是 `O(N^2)` 。

但如果你先把这些纸条**按照左端点从小到大排好序**，神奇的事情就发生了：

> **当前区间只需要和“上一个被处理的区间”比较即可。**

因为后面的区间左端点一定 `>=` 当前左端点，它不可能跳过上一个区间去和更前面的区间重叠。这就把问题从“多对多”变成了“线性扫描”。

#### 2. 如何合并区间？

假设排序后，我们维护一个“当前已合并的区间” `[start, end]`，现在来了一个新区间 `[curL, curR]`。

由于已经按左端点排序，所以一定有 `curL >= start`。此时只有两种情况：
- 如果当前区间的左端点在已排序区间中最后一个区间的右端点之后，那么它们不会重合，我们可以直接将这个区间加入结果集 merged 的末尾；
- 否则，这两个区间会重合，我们需要用当前区间的右端点更新 `end`，将其置为二者的较大值。

列表如下：

| 情况      | 条件                                     | 操作                                         | 图示                          |
| ------- | -------------------------------------- | ------------------------------------------ | --------------------------- |
| **有重叠** | `curL <= end`<br>（当前区间的左端点 <= 新区间的右端点） | 合并！更新 `end = max(end, curR)`               | `[1,4]` + `[3,6]` → `[1,6]` |
| **无重叠** | `curL > end`<br>（当前区间的左端点 > 新区间的右端点）   | 把 `[start,end]` 加入结果集，开启新区间 `[curL, curR]` | `[1,4]` 和 `[5,7]` 断开        |

> ⚠️ **关键细节**：合并时 `end` 要取 `max(end, curR)`，而不是直接赋值为 `curR`。  
> 反例：`[1,10]` 和 `[2,5]`，如果直接赋值 `end=5`，区间反而缩小了，这是错误的。

#### 3. 代码：
```cpp
// 这里将 start 和 end 替换为了 merged.back()，因为结果集数组的最后一个元素就是当前正在维护的区间，这样写会更简洁。
vector<vector<int>> merge(vector<vector<int>>& intervals) {
	if (intervals.size() == 0) return {};
	
	sort(intervals.begin(), intervals.end()); // sort能处理vector，vector内部重载了 < 运算符，排序默认为字典序
	vector<vector<int>> merged;
	for (int i = 0; i < intervals.size(); ++i) {
		int L = intervals[i][0], R = intervals[i][1];
		if (!merged.size() || merged.back()[1] < L) {
			merged.push_back({L, R});
		}
		else {
			merged.back()[1] = max(merged.back()[1], R);
		}
	}
	return merged;
}
```

| 指标  | 复杂度        | 说明                         |
| :-- | :--------- | :------------------------- |
| 时间  | `O(NlogN)` | 排序主导，线性扫描仅 `O(N)`          |
| 空间  | `O(logN)`  | 排序所需的栈空间（C++ sort），结果数组不计入 |
#### 4. 补充：

这道题的贪心主要体现在两点：
1. **优先处理左端点最小的区间**：这里的排序可以看作一个贪心策略。排序后，当前区间的左端点不可能再被更早的区间覆盖，因此可以直接确定合并区间的起点。
2. **重叠时尽量扩展右端点**：若 `curL <= end`，就更新`end = max(end, curR)`。保留更大的右端点，能覆盖更多后续区间，且不会让结果变差。

一句话总结：**排序确定不可更改的左边界，`max` 尽可能扩大右边界，每一步的局部最优最终得到全局最优。**

### 189. 轮转数组

这道题有很多做法：

#### 1. 使用额外数组：

我们可以使用额外的数组来将每个元素放至正确的位置。

用 n 表示数组的长度，遍历原数组，将原数组下标为 i 的元素放至新数组下标为 `(i+k) % n` 的位置，最后将新数组拷贝至原数组即可。

```cpp
void rotate(vector<int>& nums, int k) {
	int n = nums.size();
	vector<int> arr(n);
	for(int i = 0; i < n; i++) {
		arr[(i + k) % n] = nums[i];
	}
	nums.assign(arr.begin(), arr.end());
	// assign 是逐元素拷贝，可以直接换成 std::move，一次性拷贝整个数组
	// 即 nums = std::move(arr);
}
```

- 时间复杂度： `O(n)`，其中 `n` 为数组的长度。
- 空间复杂度： `O(n)`。

#### 2. 三次翻转法：

这玩意算是这道题巧妙且直观的一种解决方法了，仅需三次翻转。

该方法基于如下的事实：当我们将数组的元素向右移动 k 次后，尾部 `k mod n` 个元素会移动至数组头部，其余元素向后移动 `k mod n` 个位置。

我们可以先将所有元素翻转，这样尾部的 `k mod n `个元素就被移至数组头部，然后我们再翻转 `[0, (k mod n) − 1]` 区间的元素和 `[k mod n, n − 1]` 区间的元素即能得到最后的答案。

代码如下：

```cpp
class Solution {
public:
    void reverse(vector<int>& nums, int start, int end) {
        while (start < end) {
            swap(nums[start], nums[end]);
            start += 1;
            end -= 1;
        }
    }

    void rotate(vector<int>& nums, int k) {
        k %= nums.size();
        reverse(nums, 0, nums.size() - 1);
        reverse(nums, 0, k - 1);
        reverse(nums, k, nums.size() - 1);
    }
};
```

或者也可以利用 C++ 的迭代器和 `std::reverse`，就不用手写 `reverse()` 了
``` cpp
void rotate(vector<int>& nums, int k) { 
	int pos = k % nums.size(); 
	reverse(nums.begin(), nums.end()); 
	reverse(nums.begin(), nums.begin() + pos); 
	reverse(nums.begin() + pos, nums.end()); 
} 
```

- 时间复杂度：`O(n)`，其中 `n` 为数组的长度。每个元素被翻转两次，一共 `n` 个元素，因此总时间复杂度为 `O(2n)=O(n)`。
- 空间复杂度：`O(1)`。

#### 3. 环状替换：

这个方法有点吃数学理解

如果我们把每个元素从"当前位置"送到"目标位置"，再把目标位置上被挤走的元素继续送到它的目标位置……就会形成一条**链**。当这条链回到起点时，就构成了一个**环**。

例: `nums = [1,2,3,4,5,6], k = 2, n = 6` 
- 映射关系: `i` →`(i + 2) % 6` 
- 环的个数：`GCD(6, 2) = 2`
- 第一次移动：0→2→4→0 (环1: 长度3)
- 第二次移动：1→3→5→1 (环2: 长度3)

💡 **直觉理解**：每次跳 `k` 步，在模 `n` 意义下，需要跳 `n / gcd(n,k)` 次才能回到起点，所以每个环长 `n / gcd(n,k)`，共 `gcd(n,k)` 个环。

算法执行起来倒是比较简单：我们求 `gcd(n, k) = m`，然后从 `nums[0]` 到 `nums[m-1]` 跑 `m` 次回到起点的完整的环，最后的 `nums` 就是目标结果。

代码如下：
```cpp
void rotate(vector<int>& nums, int k) {
	int n = nums.size();
	k = k % n;
	int count = gcd(k, n);    // C++17 的 std::gcd，没有的话需要手动使用辗转相除法求最大公约数
	for (int i = 0; i < count; i++) {
		int current = i; 
		int prev = nums[i];
		do {
			int next = (current + k) % n;
			swap(nums[next], prev);
			current = next;
		} while (i != current);
	}
}
```

- 时间复杂度：`O(n)`，其中 `n` 为数组的长度。每个元素只会被遍历一次。
- 空间复杂度：`O(1)`。我们只需常数空间存放若干变量。

### 238. 除了自身以外数组的乘积

这似乎是一个简单的问题，可以在线性时间和空间内解决。先计算给定数组所有元素的乘积，然后对数组中的每个元素 x，将总的乘积除以 x 来求得除自身值的以外数组的乘积。

然而这样的解决方法有一个问题，就是如果输入数组中出现 0，那么这个方法就失效了。而且在问题中说明了不允许使用除法运算。这增加了这个问题的难度。（有除法就简单了 : ) ）

> **补充**：即使允许除法，处理零值也需要额外分类讨论，并不真正简单

#### 方法一：左右乘积列表

仔细观察，我们应该可以发现，如果要求 `总乘积 / nums[i]` ，好像可以用 `nums[i]` 左边的乘积 * `nums[i]` 右边的乘积。

有没有想到一个东西？—— 前缀/后缀积！

我们可以用两个数组 `pre` 和 `suf` 分别存储 `i` 处的前缀积和后缀积，需要使用两个循环来填充具体数值。

由于 `pre[i]` 存放的是 `i` 左边的所有数的乘积，而 `pre[i - 1]` 存放的是 `i - 1` 左边的所有数的乘积，少个 `nums[i - 1]`，因此有公式 `pre[i] = pre[i - 1] * num[i - 1]`；
- 对于数组 `pre`，`pre[0]` 应该为 1，因为第一个元素的左边没有元素，如果为0，后续计算将全部为 0。

同理，`suf[i] = suf[i + 1] * nums[i + 1]`

当两个数组填充完成后，由上述推导可知，`ans[i] = pre[i] * suf[i]`

代码如下：

```cpp
vector<int> productExceptSelf(vector<int>& nums) {
	int n = nums.size();
	vector<int> suf(n), pre(n), ans(n);
	
	// 处理前缀积 
	pre[0] = 1;
	for(int i = 1; i < n; i++) {
		pre[i] = pre[i - 1] * nums[i - 1];
	}
	
	// 处理后缀积
	suf[n - 1] = 1;
	for(int i = n - 2; i >= 0; i--) {
		suf[i] = suf[i + 1] * nums[i + 1];
	}
	
	// 得到结果
	for(int i = 0; i < n; i++) {
		ans[i] = pre[i] * suf[i];
	}
	
	return ans;
}
```

**时间复杂度**：`O(N)`，其中 `N` 指的是数组 `nums` 的大小。预处理 `pre` 和 `suf` 数组以及最后的遍历计算都是 `O(N)` 的时间复杂度。
**空间复杂度**：`O(N)`，其中 `N` 指的是数组 `nums` 的大小。使用了 `pre` 和 `suf` 数组去构造答案，`pre` 和 `suf` 数组的长度为数组 `nums` 的大小。


#### 方法二：空间复杂度 O(1) 的方法

尽管上面的方法已经能够很好的解决这个问题，但是空间复杂度并不为常数。（这里指的是除开结果数组外的空间）

由于输出数组不算在空间复杂度内，那么我们可以将 `pre` 或 `suf` 数组用输出数组来计算。先把输出数组当作 `pre` 数组来计算，然后再动态构造 `suf` 数组得到结果。

这里的空间优化思路和 **DP 的状态压缩（滚动变量）** 如出一辙：本来是 `ans[i] = pre[i] * suf[i]`，由于某个位置的前缀/后缀积只依赖**相邻的**前缀/后缀积，即 `suf[i]` 只依赖 `suf[i+1]`，我们可以顺理成章地将 `pre` 用 `ans` 暂存，然后仅使用 1 个变量 `R` 滚动求解 `suf[i]`，从而省掉整个后缀数组。（反过来也一样）

因此，我们可以写出如下代码：

``` cpp
vector<int> productExceptSelf(vector<int>& nums) {
	int n = nums.size();
	vector<int> ans(n);

	// ans[i] 表示索引 i 左侧所有元素的乘积
	// 因为索引为 '0' 的元素左侧没有元素， 所以 answer[0] = 1
	ans[0] = 1;
	for (int i = 1; i < n; i++) {
		ans[i] = nums[i - 1] * ans[i - 1];
	}

	// R 为右侧所有元素的乘积
	// 刚开始右边没有元素，所以 R = 1
	int R = 1;
	for (int i = n - 1; i >= 0; i--) {
		// 对于索引 i，左边的乘积为 answer[i]，右边的乘积为 R
		ans[i] = ans[i] * R;
		// R 需要包含右边所有的乘积，所以计算下一个结果时需要将当前值乘到 R 上
		R *= nums[i];
	}
	return ans;
}
```

时间复杂度：`O(N)`，其中 `N` 指的是数组 `nums` 的大小。分析与方法一相同（只优化了空间）。
空间复杂度：`O(1)`，输出数组不算进空间复杂度中，因此我们只需要常数的空间存放变量。
