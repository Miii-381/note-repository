## 一. 哈希
### 1. 两数之和

这道题题干说找 `target = a + b` 的两个数 `a` 和 `b`，但如果我们换个角度，`target` 是已知的，这里就可以转换为求 `b = target - a` ，那就有意思了。

我们需要遍历数组：对每一个 `b` ，去寻找能够满足 `a = target - b` 的那一个 `a`。

但很明显：`b` 要遍历，寻找 `a` 要遍历，时间复杂度是 `O(n^2)`，如果我们将寻找的时间复杂度降到 `O(1)` 呢？

这里就可以将整个数组塞入哈希表，哈希查询的时间复杂度就是 `O(1)` 。

但要注意，题干中只让返回一个结果，我们可以不用将数组全量塞入哈希表，可以边遍历边构建哈希表，这样有两个天然的好处：
1. 如果先全量插入，当 `target - nums[i] == nums[i]` 时，可能错误地匹配到自己（除非额外处理）。而边遍历边插，保证查到的一定是**之前出现的元素**，天然排除自身。
2. 可以提前返回：一旦找到答案，就能直接提前结束遍历返回结果，性能更佳。

具体代码如下：
``` cpp
vector<int> twoSum(vector<int>& nums, int target) {
	unordered_map<int, int> map;
	for(int i = 0; i < nums.size(); i++) {      // 遍历数组，对每一个 b
		auto it = map.find(target - nums[i]);   // 寻找满足 a = target - b 的 a
		if(it != map.end()) {
			return {it->second, i};
		}
		map[nums[i]] = i;
	}
	return {};
}
```

### 49. 字母异位词分组

首先，字母异位词 = 通过重新排列不同单词或短语的字母而形成的单词或短语，并使用所有原字母一次。也就是说，能分到一起的词的字母和其数量是相同的。我们自然可以想到两种方案：
1. 对每个词进行排序，排序后相同的 `str` 就是字母异位词；
2. 统计每个词的字母及其数量，相同的就是字母异位词；

第一种方案比较简单，拉个哈希表 `unordered_map<string, vector<string>>`，以排序后的 `str` 为键，以原始字符串为值，遍历 `strs`，进行分组，最后构建结果数组输出即可：

排序法的时间复杂度是 `O(n⋅klog⁡k)` （ `k` 为单词平均长度），当单词较长时， `log⁡k` 因子不可忽视。

```cpp
vector<vector<string>> groupAnagrams(vector<string>& strs) {
	unordered_map<string, vector<string>> map;
	for(int i = 0; i < strs.size(); i++) {
		string str = strs[i];
		sort(str.begin(), str.end());
		map[str].emplace_back(strs[i]);    // emplace_back避免字符串拷贝，且`unordered_map` 的 `operator[]` 在 key 不存在时会自动对 value 进行值初始化，不用特殊处理空键
	}
	vector<vector<string>> ans;
	for(auto& m : map) {
		ans.emplace_back(m.second);
	}
	return ans;
}
```

第二种方法有点小难：对每个 `str`，构建26个字母的统计数组，`idx` 对应字母序号，`arr[idx]` 存放字母个数，然后以该数组为键，构建哈希表，后续的工作与第一种差不多，不再赘述。

这个方法的难点在需要为数组构建单独的哈希计算函数，没了解过的话很难写出来。

但这个方法理论上**时间复杂度**更优秀：
- 时间复杂度降为 `O(n⋅k)` ，省去了排序的 `log⁡k` 因子。
- 当 `k` 较大（如长文本片段）时优势明显。
```cpp
vector<vector<string>> groupAnagrams(vector<string>& strs) {
	// 哈希计算函数，简单来说就是对数组元素的每个值相加，加一次计算一次哈希，原哈希左移一位与现哈希进行异或
	auto arrayHash = [fn = hash<int>{}] (const array<int, 26>& arr) -> size_t{
		return accumulate(arr.begin(), arr.end(), 0u, [&](size_t acc, int num) {
			return (acc << 1) ^ fn(num);
		});
	};

	unordered_map<array<int, 26>, vector<string>, decltype(arrayHash)> map(0, arrayHash);
	for(string& str : strs) {
		array<int, 26> counts{};
		int length = str.length();
		for(int i = 0; i < length; i++) {
			counts[str[i] - 'a'] ++;
		}
		map[counts].emplace_back(str);
	}
	vector<vector<string>> ans;
	for(auto& m : map) {
		ans.emplace_back(m.second);
	}
	return ans;
}
```

小补充：如果使用 C++20，`std::array` 已原生支持作为 `unordered_map` 的 `key`（标准库提供了特化 `std::hash`），**完全不需要自定义哈希函数**：
```cpp
// C++20: 直接使用，零额外代码
unordered_map<array<int, 26>, vector<string>> map;
```

但主流刷题平台基本都是 C++14/17，甚至还有C++11的 （笑）

### 128. 最长连续序列

这道题要求时间复杂度为 `O(n)`，第一眼就可以直接毙掉暴力遍历，暴力起码是 `O(n^2)` 级别

既然这道题要求查找，且限制时间复杂度，那么我们一定可以想到哈希表，哈希表的查找是 `O(1)`

看看题，好像不好使用 `unordered_map`，键值对无法构建，那么我们可以使用 `unordered_set`，只存值。

题干告诉我们数组中有最长连续序列，那么意味着这个最长连续序列肯定是排序后数组的一个子串，其肯定有个头，我们找到这个头即可：

设一个连续序列的头的值为 `num`，不难发现，如果要满足连续序列的要求，则在数组中肯定找不到 `num - 1`，否则 `num` 就不满足头的要求了。

那么整道题的思路就明了了：
- 遍历数组，对每个值 `num`，查找是否存在 `num - 1`，如果不存在，说明这个 `num` 可能就是连续序列的头（包括序列长 = 1的情况）。
- 查找到后，从 `num` 开始，一直往下找 `num + 1` 、`num + 2` 、`...` ，直到找不到为止，遍历的步数 + 1就是连续序列的长度，使用 `max(ans, length)` 更新最大值，最后返回 `ans` 即可。

代码如下：

```cpp
int longestConsecutive(vector<int>& nums) {
	unordered_set<int> set(nums.begin(), nums.end());
	int ans = 0, len = 0;
	for(int num : set) {
		if(!set.count(num - 1)) {
			len = 1;
			while(set.count(++num)) len++;
			ans = max(ans, len);
		}
	}
	return ans;
}
```

## 二、双指针

### 283. 移动零

yysy，这道题很容易让人想到冒泡交换，事实上也可以这么做，代码如下：
``` cpp
void moveZeroes(vector<int>& nums) { 
	int n = nums.size(); 
	// 相邻交换
	for (int i = 0; i < n; i++) {
		for (int j = 0; j < n - 1 - i; j++) {
			if (nums[j] == 0 && nums[j+1] != 0) {
				swap(nums[j], nums[j+1]);
			}
		}
	}
}

// 搜索交换
for (int i = 0; i < n; i++) { 
	if (nums[i] == 0) { 
	for (int j = i + 1; j < n; j++) { 
		if (nums[j] != 0) { // 找到第一个非零才交换 
			swap(nums[i], nums[j]); 
			break;          // 交换后立即跳出内层 
		} 
	}
}
```

但时间复杂度为`O(n^2)`，很巧的是，这道题爆不了 TLE，但显然是不太可行的

但如果我们换个思路：题干要求我们保留非 0 数的顺序，仅将 0 移到最后，那么最后的结果是不是分为了非 0 子数组和全 0 子数组两截？

于是，我们可以使用两个指针`i`和`j`：
- 指针 `i` 是**读指针**（快指针），负责遍历数组寻找非零元素；  
- 指针 `j` 是**写指针**（慢指针），始终指向**下一个非零元素应该填入的位置**（非 0 区的右边界）。

在任意时刻，`[0, j)` 区间内全是已处理好的非零元素，且保持了原始相对顺序；`[j, i]` 区间内的元素要么是已经被前移的非零元素（原位置废弃），要么是待处理的零。

因为 `j <= i` 恒成立。写指针永远落后于或等于读指针，所以 `nums[j] = nums[i]` 这个赋值操作，要么是在原地写回（`j==i` 时，说明前面没有零，非零元素不需要移动），要么是在覆盖一个**已经被读取过或者本身就是零**的位置，绝对不会破坏尚未被 `i` 扫描到的有效数据。

算法分两步走：
- 第一步，`i` 扫描到非零值就写入 `j` 并让 `j` 后移，这相当于把所有非零元素紧凑地”挤“到数组前端；
- 第二步，当 `i` 走完整个数组后，`j` 及其之后的所有位置必然都是多余的，直接批量赋零即可。

代码如下：
``` cpp
void moveZeroes(vector<int>& nums) {
	if (nums.size() <= 1)  return;
	
	// 一次遍历，移动0
	int j = 0, n = nums.size();
	for (int i = 0; i < n; i++) {
		if (nums[i] != 0) {
			nums[j] = nums[i];
			j++;
		}
	}
	
	// 二次遍历，为 j 及 j 之后的所有元素赋 0
	for (int i = j; i < n; i++) {
		nums[i] = 0;
	}
}
```

还有一种写法，也是双指针，但是其从遍历后赋值，变成了两个值交换。这种方法同样是`O(n)`，代码更简洁，少了一次循环，但稍微多了点写入消耗，无伤大雅：

```cpp
void moveZeroes(vector<int>& nums) {     
	int left = 0, right = 0, size = nums.size();    
	while(right < size) {         
		if (nums[right]) {             
			swap(nums[left], nums[right]);
			left++;         
		}         
		right++;     
	} 
}
```

还有一种利用标准库的邪修写法：

```cpp
void moveZeroes(vector<int>& nums) { 
	auto zero_end = remove_if(nums.begin(), nums.end(), 
		[&](int x) { return x == 0; }
	); 
	fill(zero_end, nums.end(), 0); 
} 
```

 `remove_if` 的语义是：将所有**不满足**条件（即保留）的元素按照原始顺序，紧凑地移到容器前端，返回指向新有效区间末尾的迭代器。但**被“移除”的元素仍然存在于容器中，其值处于未指定状态（valid but unspecified）**。
 
所以我们可以利用 `remove_if` 的特性，将所有 0 搬到最后。由于搬运后，原本为 0 的部分的值变成了”未指定状态“，我们必须使用 `fill` **显式赋值**这些未指定状态的元素为 0，才能保证结果正确。

### 11. 盛最多水的容器

这道题一定不能用暴力枚举，否则绝对爆 TLE

```cpp
int maxArea(vector<int>& height) {
	int n = height.size();
	int ans = 0;

	for (int i = 0; i < n; i++) {  
		for (int j = n - 1; j > i; j--) {
			int area = (j - i) * min(height[i], height[j]);
			ans = max(ans, area);
		}
	}

	return ans;
}
```

但其实这个代码就差临门一脚，该如何优化呢？

#### （1）剪枝：

我们可以发现，在我们遍历的时候，如果 `height[i] <= height[j]` ，也就是目前的**左柱子低于右柱子**，那么这里 `j` 就完全没有必要再向左移动遍历了：

- 面积 = `min(height[i], height[j]) * (j - i)`，宽度 `(j − i)` 是**单调递减**的，想要让面积变大，唯一的机会就是让 `min⁡(height[i],height[j])`变大。
- 而目前的矩形高度最高就是`height[i]`，所以面积只会不断减小，接下来的遍历就完全没有意义了，可以直接 `break`
- 也就是说，这里的 `break` 属于**及时止损**。

优化后的代码如下：

``` cpp
int maxArea(vector<int>& height) {
	int n = height.size();
	int ans = 0;
	for(int i = 0; i < n; i++) {
		for(int j = n - 1; j > i; j--) {
			int area = (j - i) * min(height[i], height[j]);
			ans = max(ans, area);
			// 关键：及时止损
			if(height[i] <= height[j]) {
				break;
			}
		}
	}
	return ans;
}
```

> 虽然加了 `break`，但在最坏情况下（例如数组严格递增 `[1,2,3,...,n]`），内层循环依然会跑满，时间复杂度**仍然是 `O(n^2)`** ，在 LeetCode 上依然会 TLE。

#### （2）双指针：

其实还可以使用双指针，将代码从`O(n^2)` 彻底优化为 `O(n)`：

我们知道：想要让面积变大，唯一的机会就是让 `min⁡(height[i],height[j])`变大。

单纯移动 `j`，可能会导致原本很长的柱子 `j` 被浪费掉。

假设当前 `height[i]<height[j]`，即左边是短板。

- **如果错误地移动右指针（长板）**： `j` 变成 `j−1` ，宽度减小。此时的短板依然是 `height[i]` ，所以新的 `min⁡(height[i],height[j−1])` **绝对不可能超过原来的 `height[i]`** 。所以面积**必然严格减小**，这一步是纯粹的浪费。
- **如果正确地移动左指针（短板）**： `i` 变成 `i+1` ，宽度虽然也减小了，但新的 `height[i+1]` **有可能**比原来的 `height[i]` 更高，从而突破当前的瓶颈，产生更大的面积。

也就是说，移动长板，面积上限会被当前的短板锁死，只会变小或不变；移动短板，才有可能找到更高的板子来突破上限。**我们是在“淘汰那些绝对不可能成为最优解的状态”**。

于是，我们可以进一步优化代码：

```cpp
int maxArea(vector<int>& height) {
	int n = height.size();
	int i = 0, j = n - 1;
	int ans = 0;
	while (i < j) {
		int area = (j - i) * min(height[i], height[j]);
		ans = max(ans, area);
		
		// 移动较短的柱子对应的指针
		if(height[i] <= height[j]) {
			i++;
		} else {
			j--;
		}
	}
	return ans;
}
```

### 15. 三数之和

拿到题的第一想法肯定是三重循环，但时间复杂度为 `O(n^3)` ，显然无法接受。这里有个示例：

``` cpp
vector<vector<int>> threeSum(vector<int>& nums) {
    vector<vector<int>> ans;
    sort(nums.begin(), nums.end()); // 关键：先全局排序
    int n = nums.size();
    
    for (int l = 0; l < n - 2; l++) {
        // 第一层去重：跳过重复的第一个数
        if (l > 0 && nums[l] == nums[l - 1]) continue;
        
        for (int m = l + 1; m < n - 1; m++) {
            // 第二层去重：跳过重复的第二个数
            if (m > l + 1 && nums[m] == nums[m - 1]) continue;
            
            for (int r = m + 1; r < n; r++) {
                // 第三层去重：跳过重复的第三个数
                if (r > m + 1 && nums[r] == nums[r - 1]) continue;
                
                if (nums[l] + nums[m] + nums[r] == 0) {
                    ans.push_back({nums[l], nums[m], nums[r]});
                }
            }
        }
    }
    return ans;
}
```

那么该如何修改？

三数之和为 0，本质上是在有序数组中寻找一种**平衡组合**。

而且我们可以发现，内层的两重循环本质是“在有序数组中找**两数之和**等于 target”

所以我们可以将这个问题拆分为“固定第一个数 + 两数之和“。这里推荐固定最左边的数，使用双指针 `l` 和 `r` 寻找中间和最右边的数

由于题目给的是无序数组，这里需要事先进行从小到大的排序：
- 排序后的数组，相同值挨在一起，指针移动就可以快速去重；
- 如果不事先排序，最后得到的三元组还需要进行排序去重，代价很高。

也就是说，排序后，我们可以将问题转化为：**固定最小的数，在剩余区间内用双指针寻找另外两个数使三者之和为 0**。排序不仅让双指针的单调性成立，还让相同值相邻，从而实现天然去重

这样就有了一个算法雏形：
- 对第一个数：初始化 `i = 0` ，`i` 需要遍历整个排序好的数组；如果 `i > 0 && nums[i] == nums[i - 1]`，则 `continue`，自然跳过重复的第一个数
- 在循环内部计算第二个数和第三个数：
	- `l = i + 1`, `r = nums.size() - 1`，`l`向右移动，`r` 向左移动，不断进行三元组计算；
	- 若三元组 `sum == 0`，则添加三元组到 `ans`，并让 `l` 和 `r` 同时前进一步；
		- 这里不用担心有问题，由于此时的三元组 `sum = 0`，如果 `r` 单独向左，仅`r` 减小，则得到的三元组一定`< 0`；同理，`l` 单独向右，仅 `l` 增大，得到的新三元组一定 `> 0`；
	- 然后对第二个数和第三个数进行去重，逻辑跟第一个数差不多。
	- 若`sum < 0`，则 `l++`；
	- 若`sum > 0`，则 `r--`；
	- 直到 `l >= r`，结束此次搜索，`i++`；
- 循环往复，直到 `i >= nums.size() - 2`

代码如下，补充了三个剪枝策略：
``` cpp
vector<vector<int>> threeSum(vector<int>& nums) {
	vector<vector<int>> ans;
	sort(nums.begin(), nums.end());
	int n = nums.size();
	
	for (int i = 0; i < n - 2; i++) {
		// 为第一个数去重
		if (i > 0 && nums[i] == nums[i-1]) continue;
		
		// ✅ 剪枝1：最小值已经 > 0，后面全为正数，不可能凑出和为0 
		if (nums[i] > 0) break;
		
		// ✅ 剪枝2：最小的三个数之和 > 0，后续不可能有解 
		if (nums[i] + nums[i+1] + nums[i+2] > 0) break;
		
		// ✅ 剪枝3：当前数与最大两数之和 < 0，当前数太小，跳过 
		if (nums[i] + nums[n-2] + nums[n-1] < 0) continue;
		
		int l = i + 1, r = n - 1;
		while (l < r) {
			int sum = nums[i] + nums[l] + nums[r];
			if (sum == 0) {
				ans.push_back({nums[i], nums[l], nums[r]});
				// 为第二和第三个数去重
				while (l < r && nums[l] == nums[l+1]) l++;
				while (l < r && nums[r] == nums[r-1]) r--;
				l++; r--;
			} else if (sum < 0) {
				l++;
			} else {
				r--;
			}
		}
	}
	return ans;
}
```

### 42. 接雨水

> 很经典的一道面试题，属于初见杀级别的，没相关知识储备完全不知道从何下笔。
> 
> 分三种方法：

#### （1）双指针（最优解）：

每个位置能够存储的雨水高度为 $\text{min}(\text{左侧最高柱子}, \text{右侧最高柱子}) - \text{该柱子高度}$，即：
$$water[i]=\min(leftMax,rightMax)-height[i] $$

其中：
- `leftMax`：左指针当前位置及其左侧的最大高度
- `rightMax`：右指针当前位置及其右侧的最大高度
    
双指针从数组两端向中间移动，遵循“哪边短，移动哪边”的规则：
- 若 `height[left] < height[right]`，计算左侧并移动左指针；
- 否则，计算右侧并移动右指针。

当 `height[left] < height[right]` 时，根据此前的移动过程，可以确定：
$$
leftMax \le rightMax  
$$

原因是：每一根被左指针处理过的柱子，在被越过时，右侧都存在一根比它更高的柱子。这些右侧边界都会被记录在只增不减的 `rightMax` 中。因此，所有参与更新 `leftMax` 的柱子都能被右侧边界兜住。

所以左侧当前位置的水位由 `leftMax` 决定：

```
ans += leftMax - height[left];
++left;
```

同理，当 `height[left] >= height[right]` 时，可以确定：

$$
rightMax \le leftMax  
$$

因此右侧当前位置的水位由 `rightMax` 决定：

```
ans += rightMax - height[right];
-- right;
```

完整代码如下：

``` cpp
int trap(vector<int>& height) {
    if (height.empty()) {
        return 0;
    }

    int ans = 0;
    int left = 0;
    int right = height.size() - 1;
    int leftMax = 0;
    int rightMax = 0;

    while (left < right) {
        leftMax = max(leftMax, height[left]);
        rightMax = max(rightMax, height[right]);

        if (height[left] < height[right]) {
            ans += leftMax - height[left];
            ++left;
        } else {
            ans += rightMax - height[right];
            --right;
        }
    }

    return ans;
}
```

每个位置只会被处理一次，因此：
- 时间复杂度：(O(n))
- 空间复杂度：(O(1))

> 如果不明白 `leftMax` 和 `rightMax`的更新过程，自己手推一次就比较清晰了

#### （2）动态规划（次优解，简单）：

动态规划的思路是：提前计算每个位置左侧和右侧的最高柱子，再套用公式。

对于位置 `i`：
$$ water[i]=\min(leftMax[i],rightMax[i])-height[i] $$
其中：
- `leftMax[i]`：位置 `i` 及其左侧柱子的最大高度
- `rightMax[i]`：位置 `i` 及其右侧柱子的最大高度

计算方式：
1. 从左向右计算 `leftMax`：
$$ leftMax[i]=\max(leftMax[i-1],height[i]) $$
2. 从右向左计算 `rightMax`：
$$rightMax[i]=\max(rightMax[i+1],height[i]) $$
3. 最后遍历每个位置，累加雨水量。

代码如下：
``` cpp
int trap(vector<int>& height) {
    int n = height.size();

    if (n == 0) {
        return 0;
    }

    vector<int> leftMax(n);
    vector<int> rightMax(n);

    // 初始化
    leftMax[0] = height[0];
    rightMax[n - 1] = height[n - 1];

    // 计算每个位置左侧的最大高度
    for (int i = 1; i < n; ++i) {
        leftMax[i] = max(leftMax[i - 1], height[i]);
    }

    // 计算每个位置右侧的最大高度
    for (int i = n - 2; i >= 0; --i) {
        rightMax[i] = max(rightMax[i + 1], height[i]);
    }

    // 计算每个位置能够接到的雨水
    int ans = 0;

    for (int i = 0; i < n; ++i) {
        ans += min(leftMax[i], rightMax[i]) - height[i];
    }

    return ans;
}
```

复杂度：
- 时间复杂度：\(O(n)\)，需要遍历数组三次
- 空间复杂度：\(O(n)\)，需要两个辅助数组

> 动态规划和双指针本质上使用的是**同一个公式**。区别在于：
> 	- 动态规划提前保存所有位置的 `leftMax` 和 `rightMax`
> 	- 双指针只维护当前需要的 `leftMax` 和 `rightMax`，把空间优化到了 `O(1)`

#### （3）单调栈：

单调栈的思路与动态规划、双指针不同：
- 动态规划、双指针是按“竖列”计算雨水；
- 单调栈是找到左右边界后，按“横层”计算雨水。

##### 思路：

栈中存放柱子的下标，并保持对应高度从栈底到栈顶单调递减：
```
栈底 → 栈顶：高 → 低
```

当遇到一根比栈顶更高的柱子时，说明：
- 当前柱子可以作为右边界；
- 栈顶柱子是低洼处；
- 弹出栈顶后，新的栈顶可以作为左边界。

此时便形成了一个可以接水的凹槽。

##### 计算方法：

假设有：
```
left      bottom          right
左边界     凹槽底部         右边界
```

凹槽宽度为：
$$width=right-left-1$$
这一层雨水的高度为：
$$ waterHeight=\min(height[left],height[right])-height[bottom] $$
因此，本次增加的雨水量为：
$$ water=width\times waterHeight $$

##### 代码如下：
``` cpp
int trap(vector<int>& height) {
	if (height.empty()) {
        return 0;
    }
    
    int n = height.size();
    int ans = 0;
    stack<int> st;

    for (int right = 0; right < n; ++right) {
        // 当前柱子比栈顶柱子高，说明可能形成凹槽
        while (!st.empty() && height[right] > height[st.top()]) {
            // 凹槽底部
            int bottom = st.top();
            st.pop();

            // 没有左边界，无法接水
            if (st.empty()) {
                break;
            }

            // 弹出 bottom 后，新的栈顶是左边界
            int left = st.top();

            int width = right - left - 1;
            int waterHeight =
                min(height[left], height[right]) - height[bottom];

            ans += width * waterHeight;
        }

        st.push(right);
    }

    return ans;
}
```

##### 为什么需要循环弹栈？

```
while (!st.empty() && height[right] > height[st.top()])
```

- 一根较高的右边界可能一次填平多个低洼层。
- 每弹出一个栈顶，就结算一层雨水，然后继续检查当前柱子是否还能填平更高的一层。

##### 总结：

单调栈维护的是一个高度单调递减的柱子序列：
1. 当前柱子不高于栈顶：直接入栈，等待右边界；
2. 当前柱子高于栈顶：弹出栈顶，将其作为凹槽底部；
3. 新的栈顶作为左边界，当前柱子作为右边界；
4. 按“宽度 × 高度”计算一层雨水。

复杂度：
- 时间复杂度：`O(n)`，每个下标最多入栈、出栈一次；
- 空间复杂度：`O(n)`，最坏情况下所有下标都进入栈。
