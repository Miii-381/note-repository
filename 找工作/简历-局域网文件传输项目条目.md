2026.06-2026.09	局域网点对点文件传输系统
独立开发者

项目描述：
本项目是在 Windows / Android 跨平台环境下开发并完成双端联调的局域网点对点文件传输系统，不依赖中心服务器，通过 UDP 组播与定向广播完成设备自动发现，基于自定义 TCP 二进制帧协议实现设备间文件直传，支持多文件任务并发调度、滑动窗口传输与双向取消握手。

项目主要内容：
1.设计并实现基于 UDP 组播（`239.255.77.77:53317`）与定向广播的设备发现服务，通过周期公告、主动查询与单播应答完成局域网内设备自动发现、保活与超时下线；
2.设计 24 字节定长大端序帧头的自定义 TCP 传输协议，控制消息使用 JSON、文件数据使用原始二进制，显式处理 TCP 字节流的粘包与拆包；
3.实现基于滑动窗口与批量 ACK 的可靠传输，接收端按块号偏移写入 `.part` 临时文件，传输完成后原子重命名为正式文件；
4.实现全局 / 单设备 / 单任务三级并发调度、多文件任务的逻辑分组，以及基于控制帧的双向取消握手与超时兜底。

项目难点：
1.实现自定义应用层协议的封帧与防御。TCP 是字节流、没有天然消息边界，采用"定长头 + 变长负载"两段式读取，配合帧头魔数校验与单帧 2 MiB 上限，既保证帧边界可确定，又避免伪造长度字段导致的内存耗尽；
2.重构取消操作的可靠收敛。最初实现只在协议层单向发送取消通知，联调时发现接收端仍会先收到 socket 层异常，无法区分"用户主动取消"与"网络故障"，导致双端任务状态长时间不收敛；据此重构为 `cancel_request` / `cancel_ack` 二阶段握手，配合超时兜底与"先排空写队列再 TCP 半关闭"的优雅关闭流程，确保双方对最终状态达成一致；
3.并发状态管理采用单 `io_context` + 单 I/O 线程的隐式 strand 模型，所有网络回调串行执行，内核业务逻辑零互斥锁，从设计层面消除数据竞争与死锁；
4.控制大文件传输的内存占用。接收端不做整文件缓存，按块号计算偏移量随机写入，传输 10 GiB 级文件时内存占用保持常数级；通过 Docker 双容器搭建真实双端环境完成压测，并定位到一处回调执行期间重设 `std::function` 导致的 SIGSEGV。

个人收获：
1.熟悉了基于 Asio Proactor 模型的异步网络编程，理解了单线程事件循环、`work_guard` 与对象生命周期管理（`shared_from_this`）的配合方式；
2.加深了对 TCP 协议栈的理解，掌握了自定义应用层协议在封帧、流控、确认与优雅关闭上的完整设计方法；
3.掌握了局域网发现类问题的排查方法：先用日志确认发送路径是否正常，再用 Wireshark 按 `udp.port == 53317` 过滤确认数据报是否真正到达，最后才排查 Windows 网络配置文件、防火墙规则与 VPN 默认路由，形成了"先确认链路、再怀疑代码"的排查顺序；
4.掌握了用 Docker 多容器搭建可复现测试环境，以及用 `iperf3` 区分"链路上限"与"应用层开销"的排查方法。
